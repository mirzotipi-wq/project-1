# Cassa — Master Engineering Plan

**Cassa is a point-of-sale operating system for 64-bit ARM retail hardware, written entirely in Zig.**
This document is the authoritative 100-phase delivery plan. Each phase is small enough to
review in one sitting, and each one ends with a written, testable exit criterion. Phases are
executed strictly in order; nothing is declared done because it compiles — it is done when the
exit criterion has been observed on QEMU or on real hardware and the evidence is recorded.

---

## 0. Mandate

| | |
|---|---|
| **Product** | Cassa POS OS — a dedicated till OS for shopping stores |
| **Architecture** | AArch64 (ARMv8.0-A baseline and newer) |
| **Language** | 100% Zig, kernel to pixels |
| **Boot** | UEFI stub on real hardware; QEMU `virt` ELF image for development |
| **Shape** | Monolithic kernel + isolated user-space services (POS, payments, printing, UI) |
| **Primary KPI** | A cashier can complete a sale, take payment, print a receipt, and close a shift — offline, on day one of a power cut, with zero data loss |

### 0.1 Non-negotiables

1. **Zig only.** Every line of executable logic — boot, kernel, drivers, filesystem, network,
   TLS, compositor, UI toolkit, and the POS application itself — is Zig source. There are no
   `.c`, `.S`, `.cpp`, Rust, Python or JavaScript files in the build. There is no libc.
2. **No borrowed kernels.** No Linux, no Zephyr, no seL4, no U-Boot. Cassa boots from firmware
   into its own entry point.
3. **Runs on any AArch64 CPU.** Compiled for the ARMv8.0-A baseline so that it runs on
   Cortex-A53/A55/A72/A76/A78/X-series, Neoverse, Apple silicon and Graviton. Hardware
   differences are discovered at boot through device tree and ACPI, never compiled in.
4. **POS-grade reliability.** No data loss on power failure, no half-committed sale, no
   unlabelled failure. Every subsystem has a defined degradation mode.
5. **Deterministic, reviewable security.** Capability-based isolation for every service,
   signed updates, encrypted storage, auditable privileged actions.

### 0.2 What "100% Zig" means precisely

| Artifact | Language | Rationale |
|---|---|---|
| Kernel, drivers, services, UI, apps | Zig | Mandate |
| Build system (`build.zig`) | Zig | Also emits the linker script |
| Linker script | Generated by Zig at build time | Keeps a second language out of the tree |
| Pad/entry stubs | Zig `naked` functions with Zig inline assembly | No separate `.S` files |
| Documentation | Markdown | Prose is not code |

The only external binaries involved in development are the Zig compiler and QEMU. Neither
ships inside the OS image.

### 0.3 Hardware support tiers

- **Tier 1 (must):** QEMU `virt` (CI), Cortex-A53/A72 boards, integrated POS terminals.
- **Tier 2 (should):** Raspberry Pi 4/5 class SBCs, NXP i.MX8, Rockchip RK3399.
- **Tier 3 (later):** Apple silicon VMs, Graviton bare metal, server-class Neoverse.

### 0.4 Targets

| Metric | Target |
|---|---|
| Cold boot → POS screen interactive | < 3.0 s |
| Tap → painted response | < 50 ms |
| Local checkout commit (scan → sale stored) | < 100 ms |
| Resident memory on 512 MB device | < 64 MB |
| Uptime with active sales, no reboot | 30 days |
| Sale durability | Zero loss on power cut mid-transaction |
| Kernel size (v1.0) | < 400 KiB text |

### 0.5 Repository layout

```
build.zig              Zig build + generated linker script + qemu runner + host tests
src/main.zig           Kernel entry, boot sequence, shell wiring
src/arch/aarch64/      CPU, MMU, exceptions, GIC, timers, SMP
src/devices/           PL011, PCIe, virtio, framebuffer, input, USB
src/kernel/            Logging, panic, heap, pmm, sched, IPC, caps, tracing
src/fs/                CASSAFS, VFS, block cache
src/net/               Ethernet, IP, TCP, UDP, DNS, TLS
src/gfx/               Surfaces, rasterizer, fonts, compositor, UI toolkit
src/pos/               Cart, pricing, tax, payments, receipts, reporting
src/user/              User-space services and the POS application
src/tests.zig          Host-side unit tests (pure logic only)
docs/                  This plan and subsystem notes
```

### 0.6 Verification strategy

1. **Host unit tests** (`zig build test`) for pure logic: allocators, codecs, tax maths,
   cart rules, font metrics, FDT/ELF parsers, protocol state machines.
2. **QEMU boot gate** (`zig build run`) — every commit must boot to a shell and pass the
   in-kernel self-test suite.
3. **Deterministic snapshot tests** for the UI toolkit (render to memory, compare hashes).
4. **Fault injection**: power-cut simulation, media errors, OOM, malformed frames.
5. **Hardware lab**: real POS terminal, receipt printer, scanner, card terminal.

## Stage A — Foundation: from reset vector to an observable kernel

### Phase 1 — Toolchain and reproducible build `[x]`
**Goal:** One command builds a bootable AArch64 image; no second language in the tree.
**Build:** `build.zig` with a freestanding target (ARMv8.0-A baseline, `+neon +fp`), a
linker script generated as a build artifact, `zig build run` for QEMU, `zig build test` for
host tests, warnings-as-errors, and a build manifest stamped with git describe.
**Done when:** `zig build` produces an ELF with a correct entry point, and a from-scratch
clone builds with no extra tooling or shell scripts.

### Phase 2 — Boot entry and handoff `[x]`
**Goal:** Take control of the CPU from firmware in a defined state.
**Build:** Naked `_start`: mask interrupts, set SP_EL1, capture the device-tree pointer,
clear BSS, detect current EL, park secondary cores, jump into `kmain`. UEFI path drops to
the same entry after `ExitBootServices`.
**Done when:** QEMU prints a boot line and the kernel stack/BSS are provably zeroed.

### Phase 3 — Early UART console `[x]`
**Goal:** Byte-accurate output before anything else exists.
**Build:** PL011 driver with FIFO handling, baud/word-length setup from the device tree,
polled TX/RX, and a `Writer` interface usable by the rest of the kernel.
**Done when:** Formatted output appears on QEMU's serial console at boot.

### Phase 4 — Kernel logging `[x]`
**Goal:** Structured, levelled, timestamped diagnostics.
**Build:** `klog` with compile-time max level, per-subsystem scopes, uptime stamps, a lock
for SMP safety, and an in-memory ring buffer that survives a panic for post-mortem dumping.
**Done when:** `klog.info`/`warn`/`err` render consistently, and the ring can be dumped.

### Phase 5 — Panic and fatal-error surface `[x]`
**Goal:** A crash is a diagnosis, not a mystery.
**Build:** Zig panic hook, `@panic`/`unreachable` capture, register dump (PC, LR, SP, ESR,
FAR), stack scan, boot-phase breadcrumb, and an explicit halt policy (watchdog reset in
production, hang in debug).
**Done when:** An intentional fault prints a labelled report instead of resetting silently.

### Phase 6 — Device tree discovery `[x]`
**Goal:** Learn the machine instead of hard-coding it.
**Build:** FDT parser (header validation, string block, node/property walk), memory node
extraction, `/chosen` bootargs/stdout-path, interrupt-controller and timer discovery.
**Done when:** Physical RAM size, UART base and GIC addresses are read from the tree and
logged, with QEMU varying `-m` sizes producing different reported totals.

### Phase 7 — Physical memory manager `[x]`
**Goal:** Hand out and reclaim physical pages safely.
**Build:** Bitmap allocator over usable RAM, reserved ranges for kernel/DTB/MMIO, single-page
and contiguous allocation, free counters by zone, and poison-on-free in debug builds.
**Done when:** Host tests cover alloc/free/coalesce accounting and QEMU reports the expected
page totals for several RAM sizes.

### Phase 8 — Kernel heap `[x]`
**Goal:** A real allocator behind `std.mem.Allocator`.
**Build:** Boundary-tag free-list allocator with splitting, coalescing, alignment support,
OOM propagation, usage accounting and debug poisoning.
**Done when:** Host tests pass a randomized alloc/free/coalesce workload with zero leaks and
no corruption, and the kernel can use `std.ArrayList`/`std.fmt.allocPrint`.

### Phase 9 — MMU and address-space discipline `[x]`
**Goal:** Caches on, W^X enforced, MMIO descriptors correct.
**Build:** 4 KiB granule page tables, MAIR/TCR setup, identity map during bring-up, normal
cacheable vs device-nGnRnE attributes, guard pages, permission API, TLB maintenance.
**Done when:** The kernel runs with MMU and caches enabled, unmapped accesses fault with a
decoded report, and a deliberate write to read-only text traps.

### Phase 10 — Exception vectors and fault taxonomy `[x]`
**Goal:** Every exception has an owner.
**Build:** 16-entry vector table (runtime-patched branch table, 2 KiB aligned), full trap
frame save/restore, ESR/ISS decoding for data/instruction aborts, SVC, alignment, and
SError, plus a fault handler that names the cause in plain language.
**Done when:** `svc`, a bad load, and an undefined instruction each produce a distinct,
accurate report instead of a hang.

## Stage B — Time, interrupts and concurrency

### Phase 11 — Interrupt controller (GICv3 + GICv2 fallback) `[x]`
**Goal:** Route and acknowledge interrupts on both generations of GIC.
**Build:** Distributor/redistributor/CPU-interface init, priority and group configuration,
SPI/PPI enable, acknowledge/EOI, spurious handling, IRQ handler registry.
**Done when:** The timer interrupt fires and is acknowledged on QEMU (GICv3) and on a
GICv2 target without code changes.

### Phase 12 — Generic timer `[x]`
**Goal:** Monotonic time and periodic ticks.
**Build:** CNTFRQ calibration from the device tree, CNTPCT read, CNTP compare programming,
1 kHz tick, one-shot deadlines, `uptime`/`sleep`/`sleepUntil` primitives.
**Done when:** Uptime advances accurately, a 1-second busy-wait is within 1% of wall clock,
and ticks survive 10^6 interrupts without drift or lost interrupts.

### Phase 13 — Interrupt framework refinement `[ ]`
**Goal:** Interrupt handlers cannot deadlock or stampede.
**Build:** Top-half/bottom-half split, IRQ-safe spinlocks, handler latency counters, storm
detection (disable a line that fires > N times per tick), and threaded IRQ support.
**Done when:** A deliberately storming line is throttled and logged, with the rest of the
system still responsive.

### Phase 14 — Spinlocks and atomics `[ ]`
**Goal:** Correct SMP primitives with deadlock detection.
**Build:** Ticket spinlock, IRQ-save/restore variants, exclusive/acquire-release helpers,
lock-order validation in debug builds, per-CPU state.
**Done when:** A contended counter test across 4 cores is exactly correct, and an intentional
ABBA lock order panics with both lock sites named.

### Phase 15 — Kernel threads and context switching `[ ]`
**Goal:** Multiple execution contexts inside the kernel.
**Build:** Thread struct, callee-saved context switch, per-thread stacks with guards, idle
thread, thread exit and reaping.
**Done when:** Two threads ping-pong a counter with correct interleaving and no stack bleed.

### Phase 16 — Preemptive scheduler `[ ]`
**Goal:** Fair, bounded-latency CPU sharing.
**Build:** Round-robin across priority classes, tick accounting, timeslice tuning, run-queue
per CPU with load balancing, scheduler statistics.
**Done when:** Three CPU-bound threads each get within 5% of their fair share, and an
interactive thread wakes with < 1 ms latency under load.

### Phase 17 — Sleep, wait queues, synchronization `[ ]`
**Goal:** Blocking without burning CPU.
**Build:** Wait queues, mutex/condvar/semaphore, sleeping mutexes, timeout-aware waits,
priority donation for lock holders.
**Done when:** A producer/consumer stress test with 4 threads passes 10^6 items with no lost
wakeups and no priority inversion beyond the donation bound.

### Phase 18 — SMP bring-up `[ ]`
**Goal:** Use every core in the terminal.
**Build:** PSCI `CPU_ON`, per-CPU stacks/trap frames/GIC init, IPI for reschedule and TLB
shootdown, boot barrier, per-CPU data accessor.
**Done when:** 4 cores report online, TLB shootdown is verified by a mapping test, and
`-smp 1/2/4/8` all boot cleanly.

### Phase 19 — Deferred work `[ ]`
**Goal:** Keep interrupt context tiny.
**Build:** Per-CPU workqueues, softirq classes, delayed work tied to the timer, cancellation.
**Done when:** Block-device completion is processed off the IRQ path, and a 10k-item
workqueue drains with bounded latency.

### Phase 20 — Tracing and self-tests `[ ]`
**Goal:** Observability that survives production.
**Build:** Boot self-test suite, per-subsystem counters, tracepoints with a ring buffer,
`kassa selftest` command, boot-time assertions.
**Done when:** Every boot runs the self-tests and reports a single pass/fail verdict.

## Stage C — Privilege, processes and IPC

### Phase 21 — EL0 and syscalls `[ ]`
**Goal:** Move code out of the kernel.
**Build:** EL0 transition, `svc` entry path, syscall table with argument validation,
`copy_from_user`/`copy_to_user` with range checks.
**Done when:** A user program prints via a syscall and cannot read kernel memory.

### Phase 22 — Address spaces `[ ]`
**Goal:** Isolated per-process memory.
**Build:** TTBR0 per process, ASIDs, map/unmap/protect, demand-zero anonymous memory,
user stack growth, guard regions.
**Done when:** Two processes at the same virtual address cannot see each other's data.

### Phase 23 — Capabilities `[ ]`
**Goal:** Authority is a first-class, transferable object.
**Build:** Capability slots, rights masks, derivation, revocation, per-process handle tables,
kernel object headers with refcounts.
**Done when:** A process without a capability cannot reach a device, and revocation cuts
access immediately.

### Phase 24 — IPC endpoints `[ ]`
**Goal:** Fast, typed message passing between services.
**Build:** Endpoint pairs, synchronous call/reply, 64-byte inline payloads plus handle
transfer, deadlines, backpressure.
**Done when:** A call/reply round trip sustains > 100k messages/s on QEMU, and a blocked
receiver never spins.

### Phase 25 — Shared memory and notifications `[ ]`
**Goal:** Bulk data without copying.
**Build:** Shared memory objects, mapping into multiple address spaces, futex-style wait and
wake, event counters.
**Done when:** Two processes exchange a 4 MiB buffer with zero copies and correct wakeups.

### Phase 26 — Processes and ELF loading `[ ]`
**Goal:** Run separately built programs.
**Build:** ELF64/AArch64 loader (segments, permissions, BSS), argv/envp, process lifecycle,
exit status propagation.
**Done when:** The POS shell launches a user-space binary from the filesystem.

### Phase 27 — Lifecycle and fault isolation `[ ]`
**Goal:** One crashing service cannot take the till down.
**Build:** Supervisor per service, restart policy with backoff, crash loop detection,
core-dump-to-storage, orphan reaping.
**Done when:** Killing the printer service in a loop leaves checkout functional.

### Phase 28 — Service registry `[ ]`
**Goal:** Services find each other without hard-coded handles.
**Build:** Namespace tree, path-based lookup, service manifests, lazy start, health probes.
**Done when:** The POS app resolves `pos://printer` at runtime and degrades gracefully when
it is absent.

### Phase 29 — Resource accounting `[ ]`
**Goal:** No single service can starve the till.
**Build:** Per-process memory/CPU/handle quotas, OOM scoring, memory pressure notifications,
watchdog escalation ladder.
**Done when:** A leaking service is capped and reported while checkout stays responsive.

### Phase 30 — Sandbox policy `[ ]`
**Goal:** Least privilege by construction.
**Build:** Declarative per-service syscall and capability manifests, W^X enforcement, no
ambient authority, policy validation at build time.
**Done when:** A deliberately compromised renderer cannot open a raw block device.

## Stage D — Devices, DMA and human interface hardware

### Phase 31 — Driver model `[ ]`
**Goal:** Probe order that is data-driven, not hand-ordered.
**Build:** Device objects, driver registration with compatible-string matching, dependency
ordering, init error isolation, hotplug notifications.
**Done when:** Disabling a device in QEMU removes its driver cleanly with a clear log.

### Phase 32 — PCIe host bridge `[ ]`
**Goal:** Enumerate the terminal's internal buses.
**Build:** ECAM config access, bus/device/function walk, BAR sizing and mapping, MSI/MSI-X
allocation, legacy INTx fallback.
**Done when:** `lspci`-equivalent output matches QEMU's device list, including BAR layout.

### Phase 33 — Virtio transport `[ ]`
**Goal:** One transport for block, net, input and GPU.
**Build:** Split virtqueue implementation, descriptor chains, feature negotiation,
interrupt coalescing, error recovery and queue reset.
**Done when:** A virtqueue echo test passes 10^5 requests under memory pressure.

### Phase 34 — Block layer `[ ]`
**Goal:** Reliable storage I/O with ordering guarantees.
**Build:** Virtio-block driver, request scheduler (simple elevator), flush/FUA handling,
retry with backoff, I/O statistics.
**Done when:** 10k random writes plus a flush survive an immediate QEMU quit with no
corruption reported by fsck.

### Phase 35 — Partition tables `[ ]`
**Goal:** Find our data on any disk layout.
**Build:** GPT primary/backup parsing with CRC validation, MBR compatibility, partition
iteration, protective-MBR handling.
**Done when:** Images produced by the installer, `sgdisk` and Windows all enumerate correctly.

### Phase 36 — Interrupt-driven console `[ ]`
**Goal:** A real terminal, not polling.
**Build:** RX interrupt ring buffer, line discipline (echo, backspace, Ctrl-C), UTF-8 decode,
flow control.
**Done when:** Typing at 115200 with heavy output loses no characters.

### Phase 37 — Framebuffer `[ ]`
**Goal:** Pixels on the panel.
**Build:** Bochs-display driver first (simple linear framebuffer), virtio-GPU second, HDMI
modesetting later; EDID parsing, double buffering, panic-to-screen handoff.
**Done when:** A test pattern renders at the panel's native resolution and panics are visible
on screen, not just serial.

### Phase 38 — Input subsystem `[ ]`
**Goal:** Keys, touch, scanner.
**Build:** Event queue, virtio-keyboard, USB HID boot keyboard, absolute-pointer touch,
barcode-scanner HID fast path with prefix/suffix parsing, key remapping.
**Done when:** A scanned barcode reaches the POS app as one atomic event in < 20 ms.

### Phase 39 — USB host stack `[ ]`
**Goal:** Real retail peripherals.
**Build:** xHCI controller init, port reset, enumeration, descriptor parsing, HID and
CDC-ACM classes, hub support, hotplug.
**Done when:** A USB keyboard, barcode scanner and serial card terminal all enumerate and work
across replug cycles.

### Phase 40 — Watchdog and power `[ ]`
**Goal:** Recover from hangs; behave on power loss.
**Build:** Hardware watchdog kick from the scheduler, brown-out detection hooks, thermal
throttling, graceful shutdown path that flushes the journal.
**Done when:** A forced kernel hang resets the terminal and boots to a consistent state.

## Stage E — Storage and filesystems

### Phase 41 — CASSAFS format `[ ]`
**Goal:** A crash-safe filesystem designed for till workloads.
**Build:** Log-structured design, CRC32C on every record, A/B superblocks, inode tree,
extent allocation, free-space map, on-disk versioning.
**Done when:** The format is documented and a reference dump/verify tool exists (in Zig).

### Phase 42 — Mount and read path `[ ]`
**Goal:** Read files fast and safely.
**Build:** Mount, inode lookup, directory iteration, extent reads, integrity verification,
corruption reporting.
**Done when:** A 100k-file tree mounts and random-reads within 2% of page-cache speed.

### Phase 43 — Write path and recovery `[ ]`
**Goal:** Power cut at any instant, no corruption.
**Build:** Append-only journal, checkpointing, garbage collection, atomic rename,
`fsync` semantics, replay on mount.
**Done when:** 1,000 randomized power-cut injections leave a mountable filesystem with all
acknowledged writes present.

### Phase 44 — Block and page cache `[ ]`
**Goal:** Predictable performance under load.
**Build:** LRU page cache, write-back with bounded dirty pages, readahead, cache pressure
accounting.
**Done when:** Checkout commit latency stays under 100 ms while a catalog import runs.

### Phase 45 — FAT32 reader `[ ]`
**Goal:** Import from vendor USB sticks.
**Build:** FAT32 read-only driver, long file names, cluster chains, mount integration.
**Done when:** A catalog import reads a 10k-row CSV from a FAT32 stick.

### Phase 46 — VFS `[ ]`
**Goal:** One interface for all storage.
**Build:** Mount points, path resolution, file operations, permissions, file locking,
inotify-style change notifications.
**Done when:** Paths resolve identically across CASSAFS, FAT32 and tmpfs.

### Phase 47 — Retail data model `[ ]`
**Goal:** The schema a store actually needs.
**Build:** Products, variants, barcodes, prices, tax classes, promotions, users, roles,
receipts, shifts, drawers, terminals, suppliers.
**Done when:** A full day of sales can be represented and queried without schema changes.

### Phase 48 — Transactional sale log `[ ]`
**Goal:** A sale is committed or it never happened.
**Build:** Idempotent transaction records, write-ahead ordering with CASSAFS, replay,
sequence numbers, terminal identity stamping.
**Done when:** Duplicate submissions after a network retry never double-count a sale.

### Phase 49 — Storage health `[ ]`
**Goal:** Fail predictably, not suddenly.
**Build:** Bad-block handling, read-retry policy, eMMC/SD health counters, fsck, pre-failure
warnings surfaced in the supervisor UI.
**Done when:** Simulated media errors reduce to retries and warnings without data loss.

### Phase 50 — Snapshots and recovery `[ ]`
**Goal:** Roll back a bad update or configuration.
**Build:** Copy-on-write snapshots, rollback, factory reset that preserves audit logs when
policy allows, export of a support bundle.
**Done when:** A corrupted config rolls back to the last known-good snapshot in one command.

## Stage G — The POS application

### Phase 61 — Cart engine `[ ]`
**Goal:** Model a sale correctly, including its edge cases.
**Build:** Line items, quantities, unit-price resolution, modifiers, bundles, weighed goods,
price overrides with audit, sale-level totals.
**Done when:** Property tests over random carts match a reference calculator exactly.

### Phase 62 — Tax and rounding `[ ]`
**Goal:** Legally correct totals anywhere.
**Build:** Inclusive/exclusive tax, per-line vs per-sale, rounding strategies (banker's,
half-up, Swedish), multi-jurisdiction rules, exemption certificates.
**Done when:** Reference vectors for 12 jurisdictions pass to the cent.

### Phase 63 — Promotions and loyalty `[ ]`
**Goal:** Promotions that cannot produce a negative-margin surprise.
**Build:** Rule engine (conditions/actions), stacking and exclusivity policy, coupons,
member pricing, points accrual and redemption.
**Done when:** A 20-rule promotion set resolves deterministically in < 2 ms per cart.

### Phase 64 — Tender abstraction `[ ]`
**Goal:** Any payment method, one interface.
**Build:** Cash, card, gift card, voucher, account, split tender, partial payment, change
calculation, cash rounding.
**Done when:** Split-tender combinations always balance to zero, verified by property tests.

### Phase 65 — Card terminal integration `[ ]`
**Goal:** Take card payments in the real world.
**Build:** PED transport (USB CDC-ACM and IP), ISO 8583 subset, EMV flow orchestration,
timeouts and reversal on ambiguity, offline floor limits.
**Done when:** Approved, declined, timeout, and reversal scenarios all reconcile against a
simulated acquirer.

### Phase 66 — Receipts and printing `[ ]`
**Goal:** A receipt every customer accepts.
**Build:** Receipt template engine, ESC/POS driver over USB/serial/network, 40/42-column
layout, logo rasterization, barcode/QR rendering, kitchen and return slips, reprint with
watermark.
**Done when:** A printed receipt scans back to the correct transaction QR code.

### Phase 67 — Cash management `[ ]`
**Goal:** Count the drawer, prove the money.
**Build:** Drawer kick, cash in/out, paid-in/paid-out, shift open/close, blind close, X and
Z reports, denomination counting, variance tracking.
**Done when:** Z-report totals reconcile with the transaction log to the cent.

### Phase 68 — Returns and overrides `[ ]`
**Goal:** Handle the messy half of retail.
**Build:** Receipt lookup, partial returns, exchanges, void/refund with reason codes, manager
override with credentials, immutable audit entries.
**Done when:** Every override is attributable to a user, timestamp and reason.

### Phase 69 — Offline-first sync `[ ]`
**Goal:** The store keeps selling when the internet does not.
**Build:** Durable outbox, catalog delta sync, price/promo updates, idempotent replay,
conflict resolution policy, sync health UI.
**Done when:** 8 hours offline, then reconnect, reconciles with zero duplicates.

### Phase 70 — Cashier flows `[ ]`
**Goal:** The fastest possible sale.
**Build:** Scan-first flow, search by name/SKU/barcode, quick keys, favorites, suspend and
recall, customer display, barcode label printing, keyboard shortcuts.
**Done when:** A trained cashier completes a 10-item sale in under 15 seconds.

## Stage H — Platform services

### Phase 71 — Network stack core `[ ]`
**Goal:** Own our packets.
**Build:** Virtio-net driver, Ethernet, ARP, IPv4/IPv6, ICMP, DHCP client, MTU and fragment

## Stage I — Security and hardening

### Phase 81 — Secure boot chain `[ ]`
**Goal:** Only our code runs.
**Build:** UEFI signature verification of the loader, measured boot log, kernel signature
check, rollback protection with monotonic counters.
**Done when:** A modified kernel image is refused with a verifiable reason.

### Phase 82 — Kernel hardening `[ ]`
**Goal:** Make exploitation expensive.
**Build:** KASLR, guard pages, W^X, PAN/UAO, hardened allocator (freelist integrity, quarantine),
stack overflow detection, `ro_after_init`, pointer authentication where available.
**Done when:** A suite of kernel exploitation primitives fails against the hardened build.

### Phase 83 — Storage encryption `[ ]`
**Goal:** A stolen till yields no customer data.
**Build:** Per-device data keys, AES-XTS sector encryption, key wrapping, secure-element or
derived-key storage, crypto erase.
**Done when:** Pulling the eMMC yields no readable sale data; crypto erase completes in < 5 s.

### Phase 84 — PCI-DSS-aligned controls `[ ]`
**Goal:** Satisfy payment-industry requirements by design.
**Build:** Key management lifecycle, PIN entry isolation, PAN masking and truncation, no
card data at rest, access control logs, change management trail.
**Done when:** A controls matrix maps every requirement to code and test evidence.

### Phase 85 — Threat model and pen test `[ ]`
**Goal:** Know our attackers.
**Build:** STRIDE model per component, attack-surface inventory, external penetration test,
remediation backlog with severity SLAs.
**Done when:** No open critical/high findings remain untriaged.

### Phase 86 — Fuzzing and property tests `[ ]`
**Goal:** Parsers that cannot be crashed or fooled.

tests for pricing, tax and tender maths; continuous fuzzing in CI.
